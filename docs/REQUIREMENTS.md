# 需求与验收

## 目标

用户提供的整体架构作为功能分层参考；不得把 Meshy 未公开内部结构作为已知实现。原始视频：https://www.youtube.com/watch?v=r-413N5n0i8 。官方标题为 Custom Pose: Generate 3D Characters from Images in ANY Pose!，官方教程明确要求角色图与姿势参考图。

## 功能范围

| 编号 | 用户能力 | 验收条件 |
| --- | --- | --- |
| R01 | 上传角色图与前/左/右/背视图 | 内容解码验证、方向校正、尺寸限制、图片可预览 |
| R02 | 本地轻量去背景 | U²-NetP 权重校验、本地 CPU 推理、无运行时国外依赖 |
| R03 | 自定义姿势或 A/T 姿态 | 千问多图编辑；保存中间图，用户确认后才开始 3D；不能保证与 Meshy 同质 |
| R04 | 图生 3D | 国内混元 API，真实任务 ID、错误、状态持久化 |
| R05 | 智能拓扑 | 独立阶段；先拓扑再生成纹理，避免破坏 UV |
| R06 | PBR 纹理 | 使用角色参考图；输出服务返回的实际材质资产 |
| R07 | 自动绑骨 | 仅用户声明为中性 A/T 姿态的角色；禁止自定义动态姿势直接绑骨 |
| R08 | 模型预览与导出 | 本地 GLB 预览、实际返回文件下载；FBX 通过云格式转换，不改后缀冒充转换 |
| R09 | 可维护性 | 各模块技术文档、依赖锁、接口测试、逐任务 Git 提交 |
| R10 | 故障可恢复 | 已提交任务重启后继续查询；提交结果不确定时禁止自动重复扣费提交 |

## 验收边界

- 真实图生 3D 需要腾讯云 AI3D 服务开通及凭据；姿势编辑需要百炼凭据。
- 当前机器没有检测到 `nvidia-smi`，不把大型 GPU 模型当作已安装能力。
- 多视角必须属于同一对象与同一姿势；姿势变换后不能继续使用原姿势的多视角图。
- 质量验收至少包含 5 组角色/姿势对：轮廓、肢体方向、遮挡、身份/服饰一致性、3D 多角度、材质和下载后的可打开性。
- 标准姿态生成仍需人工检查，不能把图像编辑指令当作骨骼约束的确定性保证。
- 单用户本地工作台不直接部署公网；生产化、多租户、分布式 GPU 服务属于后续版本。
